# 03-ISOTYPE信息图｜专项项目

> **项目属性：独立专项研究 / 基础设计方法与视觉语言系统**  
> **分类边界：ISOTYPE 不属于原有五类信息组织类型，而是一种可跨类型使用的基础设计方法。** 本项目独立建档，集中研究其历史脉络、符号系统、视觉编码、信息叙事、案例与可复用设计规则。

## 1. 概念定位

ISOTYPE 是 **International System of Typographic Picture Education** 的缩写，通常译为“国际图画教育系统”。它由奥托·纽拉特（Otto Neurath）及其团队在 20 世纪发展，重要的视觉设计实践与图形绘制工作与格尔德·阿恩茨（Gerd Arntz）等人相关。

ISOTYPE 的核心不是某一种固定版式，而是一套以标准化图形符号传递社会、经济、人口等复杂信息的视觉表达方法。它通过简化、统一、重复的图像符号，将抽象数据转化为便于理解、比较和记忆的视觉语言。

## 2. 为什么它是“基础设计方法”，而不是信息图形类型

信息图形类型通常根据**信息之间的组织关系**划分，例如时间先后、上下层级、类别清单、字母顺序或地理空间关系。

ISOTYPE 关注的则是**信息如何被视觉化表达**：如何建立符号系统、如何让图形代表明确对象、如何通过重复单位表达数量，以及如何用一致的视觉语法降低理解门槛。

因此：
- “层级型 / 编年型 / 编目型 / 字母表型 / 地理图形”回答的是：信息按什么关系组织？
- “ISOTYPE”回答的是：信息如何通过标准化图像符号被表达和理解？

同一张图可以同时具有某一种信息组织类型，并采用 ISOTYPE 方法进行视觉编码。不能仅因为画面使用了人物小图标或重复符号，就直接判定为 ISOTYPE；需要检查其符号是否构成有规则、可解释、可比较的视觉系统。

## 3. 核心设计原则

1. **图像符号标准化**：同一对象使用稳定、统一、可识别的图形样式，避免同一含义反复更换符号。
2. **一符一义，语义明确**：符号与对象或概念之间建立清晰对应，必要时通过图例、标题和注释解释。
3. **重复单位表达数量**：以相同图形单元的重复表示数量或规模；一个符号代表多少对象，必须明确说明。
4. **避免随意放大图标**：表达数量时优先增加符号数量，而非只放大单个图标面积，以免夸大视觉差异。
5. **图形简化与可辨识并重**：删去非必要细节，但保留识别对象所需的关键特征。
6. **建立一致的视觉语法**：统一符号比例、线条、方向、排列、间距、色彩和组合规则。
7. **面向公众理解**：控制阅读门槛，使非专业读者也能借助图像、标题和图例理解信息。
8. **以比较和叙事组织信息**：通过并列、分组、序列、对照和空间排列，让数据关系能够被直观感知。

## 4. 典型视觉编码

| 编码维度 | ISOTYPE 常见做法 | 分析时需要记录 |
|---|---|---|
| 图形符号 | 人物、物件、交通工具、建筑等简化图形 | 符号代表什么对象，识别特征是什么 |
| 数量 | 重复相同图形单元 | 单个符号代表的数量及是否存在半单位 |
| 比较 | 不同组别使用同规格符号并列 | 比较对象、比较基准和排列顺序 |
| 分类 | 用位置、分组、局部色彩区分类别 | 分类依据与分组规则 |
| 色彩 | 少量、稳定的功能性色彩 | 色彩是否承担类别、状态或强调含义 |
| 空间 | 网格、行列、阵列或分组布局 | 阅读方向、单位间距及组间关系 |
| 注释 | 标题、图例、单位说明、来源 | 是否解释符号含义、比例和数据口径 |

## 5. 典型构成流程

1. **明确主题与受众**：确定要解释的问题，以及读者需要理解的核心信息。
2. **整理数据与事实**：核对数据来源、统计口径、时间范围和单位。
3. **确定信息关系**：判断数据之间是时间、层级、类别、顺序、地理还是其他关系。
4. **建立符号词汇表**：为关键对象设计简洁、稳定、可辨识的图形符号。
5. **制定数量规则**：明确一个图形代表多少实际对象，必要时说明不足一个单位的处理方式。
6. **组织版面与阅读路径**：通过排列、分组、对照和留白建立清晰的阅读秩序。
7. **补充图例与说明**：解释符号含义、单位、数据来源和统计口径。
8. **测试理解与修订**：检查读者能否正确识别符号、读出数量并理解比较关系。

## 6. ISOTYPE 与五类信息图形的关系

| 五类信息组织类型 | 与 ISOTYPE 的结合方式（示例） |
|---|---|
| 01 编年型 | 用标准化图形符号呈现不同时期的人口、事件或社会变化 |
| 02 层级型 | 用统一符号呈现组织、资源或社会结构中的不同层级 |
| 03 编目型 | 用标准化图形建立类别清单、对象目录或分类比较 |
| 04 字母表型 | 用统一图形语言辅助字母、词条或知识条目的索引 |
| 05 地理图形 | 将标准化符号放置于地图或空间位置，表达地域分布 |

以上是方法层面的组合示例，不代表每个案例都必须使用 ISOTYPE，也不意味着 ISOTYPE 本身属于上述任何一种类型。

## 7. 案例判断与入库规则

分析新案例时，采用“双层标注”，不要把方法标签误写成类型：

- **第一层：信息组织类型**——先根据主要信息关系判断是否属于五类之一；若不适用，注明“跨类型 / 暂不归类”，并说明原因。
- **第二层：设计方法标签**——判断是否采用 ISOTYPE。只有当案例存在系统化、标准化的图像符号，并以明确规则承担信息表达（尤其是重复单位、数量比较或符号语法）时，才添加此标签。
- **允许多标签**——例如“02 层级型 + ISOTYPE 方法”，表示案例的信息结构是层级型，视觉表达采用 ISOTYPE 方法。
- **避免误标**——单纯装饰性图标、零散插画、普通 pictogram 点缀，或没有稳定语义与编码规则的重复图案，不足以认定为 ISOTYPE。

## 8. 案例分析时的专项检查项

- 符号是否具有明确、稳定的语义？
- 同一对象是否使用一致的图形单位？
- 一个符号代表多少实际数量？是否清楚标注？
- 数量比较是否通过重复单位完成，是否存在面积误导？
- 不同类别是否共享统一的图形语法？
- 图例、标题、单位、来源是否足以支持独立阅读？
- 符号系统是否真正参与信息编码，而非仅作装饰？
- 去掉装饰元素后，信息关系和数据含义是否仍然成立？

## 10. 项目归档结构建议

本专项项目后续可持续扩展为以下模块：

- `理论与历史/`：ISOTYPE 的发展背景、理论文献、关键人物与设计实践。
- `符号系统/`：标准化图形符号、符号词汇表、造型规则与语义映射。
- `案例分析/`：每个案例独立分析，记录原图、出处、视觉编码、信息结构与叙事方式。
- `基础数据集/`：保存案例涉及的原始数据、清洗数据、衍生数据及字段说明；未经核验的数据标注待核实。
- `示例图/`：按案例名称归档研究图像，并记录来源与使用说明。
- `方法模板/`：沉淀可复用的分析表、符号设计规范和案例判断清单。
