## 案例归档规范
- 类型目录维护总论文档，并根据新增案例实时更新案例索引、共性规律和类型边界。
- 每个案例建立独立分析报告，不将多个案例混写在同一报告中。
- 每个案例必须同时归档可复用的基础数据集，优先使用 CSV；数据表每行代表一条观测记录，每列代表一个字段，每个单元格只允许一个值，不得把多个数据合并进同一单元格。
- 基础数据集放在对应案例的“案例分析报告/数据集/”目录，并配套数据集说明，注明字段定义、单位、数据来源、统计时间、转换方法及核验状态。
- 原始数据、清洗后数据和衍生数据应分开保存；无法从案例中确认的数据标注待核实，不得补造。
- 案例图片统一放入对应的“示例图”目录，文件名与案例名称一致。
- 研究报告必须记录可核实的图片、文字与数据来源；未确认的信息标注“待核实”。
- 每份报告统一分析数据结构、统计图形应用、视觉编码、信息框架、叙事框架及信息图形类型学分类。
- 每个案例采用“双层标注”：先判定信息组织类型，再标注所使用的基础设计方法（如 ISOTYPE）；方法标签可以跨类型复用，不得将其误归为新的信息图形类型。

## 新增案例步骤
1. 选择最匹配的类型目录或常用图形子目录。
2. 复制该目录的分析报告模板并按案例命名。
3. 将案例图像放入“示例图”目录。
4. 整理并上传案例基础数据集及数据说明，检查每列字段唯一、每格单值。
5. 完成分析后更新对应类型总文档的案例索引和归纳。
6. 若案例使用了可复用的基础设计方法，添加相应方法标签（可多选），并说明其与信息组织类型的关系。
